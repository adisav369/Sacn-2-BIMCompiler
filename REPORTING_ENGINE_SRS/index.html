    Reporting Engine — BIM PrintFormat Designer (OSGi Plugin)¶

    Foundation: BACK_OFFICE_SRS (ReportDAO stub) · TIER1_SRS (4D-7D DAOs) · DATA_MODEL (ERP schema) · DocValidate (compliance rules) · STANDARDS_COMPLIANCE_SRS (SC certificates)

    The 5D DAOs produce numbers. The Reporting Engine turns those numbers into documents that contractors sign, authorities stamp, and directors present to boards.

    Every compiled building already carries 4D schedules, 5D costs, 6D carbon, 7D asset data, and Standards Compliance certificates. None of that is a deliverable until it has a layout — a header, a logo, a column order, a signature block, a clause reference, a summary total. This module is the layout engine. It follows iDempiere's AD_PrintFormat architecture exactly: reports are metadata rows, not code. Users open the PrintFormat designer, drag columns, change fonts, reorder sections — and the engine regenerates the output. No developer involvement per template change.

    Why iDempiere PrintFormat — Not a Custom Report Builder¶

    iDempiere's report architecture is the most mature open-source ERP report model in existence. It has been battle-tested across 20 years of production deployments in manufacturing, distribution, and finance. The key properties:

    • Reports are data, not code. AD_PrintFormat + AD_PrintFormatItem rows define layout entirely. Java generates output from those rows.
    • User-editable without developer. The PrintFormat designer is a Swing GUI inside iDempiere. Users drag columns, set fonts, add images, change groupings — changes take effect immediately on next print.
    • Reusable across document types. The same engine prints invoices, purchase orders, picking lists, and — now — BIM BOQs, compliance certificates, and floor plan schedules.
    • OSGi-native extension. A plugin registers its own AD_PrintFormat rows at activation. Users get the new report types without database scripts.

    This is the correct foundation. Building a custom report designer would reproduce 20 years of solved problems. Adopting AD_PrintFormat means the plugin delivers production-grade output on day one.

    Plugin Registration (plugin.xml)¶

    <?xml version="1.0" encoding="UTF-8"?>
<?eclipse version="3.4"?>
<plugin>

  <!-- Model Validator — seeds AD_PrintFormat rows on first activation -->
  <extension point="org.adempiere.base.IModelValidatorFactory">
    <ModelValidator
        class="org.red1.bim.report.BIMReportActivator"
        componentName="BIM Reporting Engine"/>
  </extension>

  <!-- PrintFormat renderer — intercepts print action for BIM document types -->
  <extension point="org.adempiere.base.IPrintFormatFactory">
    <PrintFormat
        class="org.red1.bim.report.BIMPrintFormatFactory"
        documentTypes="BIM_BOQ,BIM_SCHEDULE,BIM_2D,BIM_COMPLIANCE,BIM_FINANCIAL"/>
  </extension>

  <!-- Report views — registered as AD_ReportView rows -->
  <extension point="org.adempiere.base.IReportViewProvider">
    <ReportView
        class="org.red1.bim.report.BIMReportViewProvider"/>
  </extension>

  <!-- Menu contributions — adds "BIM Reports" under Tools menu -->
  <extension point="org.eclipse.ui.menus">
    <menuContribution locationURI="menu:tools">
      <command commandId="org.red1.bim.report.openDesigner"
               label="BIM Report Designer"
               icon="icons/report_bim.png"/>
    </menuContribution>
  </extension>

</plugin>

    Report Catalogue — All 16 Templates¶

    Category 1 — Malaysian Standards¶

    ID Report Authority Basis Data Source
    BIM-RPT-01 CIDB Bill of Quantities CIDB / JKR PWD 203A sections CostDAO × output.db elements
    BIM-RPT-02 JKR Contract Cost Summary JKR PWD 203A Appendix CostDAO totals + PC/provisional sums
    BIM-RPT-03 CIDB IBS Content Score CIDB IBS Manual 2010 STR discipline elements × IBS category
    BIM-RPT-11 UBBL Compliance Summary CIDB / DBKL UBBL 1984 compliance_proof.db SC_Run

    CIDB BQ section structure (PWD 203A standard):

    Section A  — Preliminary and General
Section B  — Substructure (earthworks, piling, foundations)
Section C  — Concrete Frame (columns, beams, slabs, staircases)
Section D  — Brickwork and Blockwork
Section E  — Roofing
Section F  — Woodwork (doors, windows, frames)
Section G  — Metal Work
Section H  — Plumbing and Drainage (MS 1228)
Section I  — Electrical Installation (MS IEC 60364)
Section J  — Fire Protection (MS 1910 / UBBL Part VII)
Section K  — Air Conditioning and Mechanical Ventilation (MS 1525)
Section L  — External Works
Provisional Sums
PC Sums
Contingencies

    Each section maps to one or more ad_org_id discipline codes in the compiler's BOM. The renderer reads elements from output.db filtered by discipline and IFC class, joins to M_Product for pricing, groups by section.

    IBS Content Score — three systems:

    System 1 — Structural (max 50 pts)
  Precast concrete columns/beams/slabs → IBS score per m²
  Steel frame → IBS score per tonne
  Prefabricated timber frame → IBS score per m²

System 2 — Wall (max 40 pts)
  Precast concrete panels → score per m²
  Lightweight steel framing → score per m²
  Prefab blockwork → score per m²

System 3 — Other (max 10 pts)
  Precast stairs → score per flight
  Prefab roof truss → score per m²

    Score = (IBS component area / Total floor area) × system weight. Minimum IBS score for CIDB certification: 70 points. Source: CIDB IBS Manual 2010. Status: RESEARCHED. Pending: verify 2022 amendment.

    EVM fields (BIM-RPT-13):

    These are financial constructs, not BIM quantities. Their source is the intersection of CostDAO (what elements cost) and ScheduleDAO (when elements are scheduled). No EVM-specific data is invented — the compiler already has both halves.

    PV  (Planned Value)     = scheduled cost to date from ScheduleDAO
EV  (Earned Value)      = % complete × BAC from CostDAO actuals
AC  (Actual Cost)       = purchase orders + labour records (C_Order actuals)
SPI (Schedule Perf.)    = EV / PV
CPI (Cost Perf.)        = EV / AC
EAC (Est. at Complete)  = BAC / CPI
VAC (Variance at Compl) = BAC - EAC

    Status: CostDAO provides BAC and element costs. AC requires real purchase order actuals — that is a GAP until iDempiere procurement is wired. EVM reports stub AC = 0 until wired. Mark as DRAFT in report header.

    Report Designer UX — What Users See¶

    The plugin adds one menu item: Tools → BIM Report Designer

    This opens iDempiere's standard PrintFormat window, pre-filtered to show only BIM report templates (AD_PrintFormat rows with Name LIKE 'BIM %').

    From this window a user can:

    1. Select any template — see columns in the left panel
    2. Drag columns to reorder — change will apply on next print
    3. Double-click a column — edit font, alignment, width, label, number format
    4. Add a column — pick from available AD_Column rows for that virtual table
    5. Delete a column — remove from printed output (data still computed)
    6. Set group-by — change which column triggers a subtotal break
    7. Edit header/footer — add company logo (image), change stamp text
    8. Preview — render to PDF preview against current active building

    No Java changes per template edit. This is the PrintFormat designer contract.

    Implementation Phases¶

    Phase RE-1 — Scaffold (1 session)¶

    OSGi bundle compiles clean. BIMReportActivator seeds 16 AD_PrintFormat rows and virtual AD_Table/AD_Column rows on activation. PrintFormat window shows all 16 BIM templates. Gate: plugin installs without error, templates visible in iDempiere UI.

    Phase RE-2 — CIDB BQ (2 sessions)¶

    BIMReportDAOImpl.getBOQLines() reads output.db elements, joins to M_Product for pricing, groups by PWD 203A section mapping. BOQRenderer produces PDF. Gate: DemoHouse_MY produces a valid CIDB BQ PDF with all sections, section totals, and grand total matching CostDAO.costBreakdown().

    Phase RE-3 — Drawing Schedules (1 session)¶

    Room, door, window schedules from elements_meta + spatial_structure. Gate: SampleHouse produces door schedule with 7 doors, room schedule with correct areas matching output.db room_areas view.

    Phase RE-4 — Compliance Certificate (1 session)¶

    ComplianceRenderer reads compliance_proof.db. Gate: DemoHouse_MY UBBL summary PDF matches SC_Run totals. Certificate ID printed in footer.

    Phase RE-5 — Financial Reports (2 sessions, after EVM actuals wired)¶

    EVM, P&L, cash flow from CostDAO + ScheduleDAO. DRAFT watermark when AC = 0. Gate: EVM report for DemoHouse_MY renders with correct PV, correct BAC, and DRAFT watermark on AC column.

    Phase RE-6 — Malaysian Standards (1 session)¶

    IBS content score. UBBL section mapping. Gate: DemoHouse_MY IBS score computed against three systems, total ≥ 0 (actual certification depends on structural system choices in BOM).
