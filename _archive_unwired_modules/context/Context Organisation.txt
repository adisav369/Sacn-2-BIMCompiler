# Context Organisation — Claude Code Strategy

## Auto-Loaded Every Session (keep concise)
1. **CLAUDE.md** — prime rule, standing rules, sacred files (~35 lines)
2. **MEMORY.md** — doc map, entry points, architecture, preferences (~65 lines)

## Read at Session Start
3. **PROGRESS.md** — current state, gates, what's next

## Load on Demand
4. **context/SCHEMA_QUICKREF.md** — compact DB table/row counts
5. **memory/*.md topic files** — architecture, conventions, traps, BOM model, TB-LKTN, WMS locator, git
6. **docs/*.md** — deep dives (11 docs, indexed in MEMORY.md doc map)

## Maintenance Rules
- Update MEMORY.md verb/witness count after each session that changes them
- Delete topic files when their content is fully absorbed or obsolete
- Never create CONTEXT_*.md duplicates of existing docs — use doc map pointers
- No paste templates, no repo splits — Claude Code handles context natively
