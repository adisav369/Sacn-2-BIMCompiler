## Context: Compiere/e-Evolution BOM Model

In standard Compiere (Red1's original BOM Drop), M_BOM_Line has:
- **BOMQty** (DECIMAL) + **C_UOM_ID** — qty interpreted through UOM lens
- **ComponentType** — Component/Phantom/Option/Variant
- BOM Drop interprets qty=2345 + UOM=MM as "2345mm of this material"

Our M_BOM_Line currently has qty (INTEGER) and qty_type (VARIABLE/FIXED)
but no UOM. The UOM is the missing signal that tells the walker whether
qty is a count (EA) or a length (MM/M).

public static final String COLUMNNAME_c_uom_id = "c_uom_id";

/** Unit of Measure — EA (each, default), MM, M, KG, M2, M3.
 *  When UOM is a length unit (MM/M), qty is the dimension along forward_axis.
 *  Follows iDempiere C_UOM_ID convention from Compiere BOM Drop. */
public String getUomId()  { return get_ValueAsString(COLUMNNAME_c_uom_id); }
public void setUomId(String v) { set_Value(COLUMNNAME_c_uom_id, v); }

/** True if this line's qty represents a length (MM or M), not a count. */

    String uom = getUomId();
    return "MM".equals(uom) || "M".equals(uom);
}

### 3. InterimWorkshop.java (new class)

Location: `DAGCompiler/src/main/java/com/bim/compiler/bom/walker/InterimWorkshop.java`

```java
/**
 * Runtime mesh computation for variable-length MEP pieces.
 *
 * <p>Like a contractor's workshop: takes a standard piece template from
 * component_library.db, recomputes the mathematical primitive (cylinder,
 * box, torus arc) at the required length. LOD (face count, tessellation)
 * from the library template. Dimensions from the BOM line (qty + c_uom_id).
 *
 * <p>This is NOT parametric mesh generation. MEP pieces are mathematical
 * primitives — their shape is fully determined by diameter + length.
 * Materials are flat RGBA per face (no UV mapping). A shorter cylinder
 * has shorter side faces with the same uniform colour. No distortion.
 *
 * <p>Results are ephemeral — not stored back to library or BOM.
 *
 * <p>Implementing DISC_VALIDATION_DB_SRS.md §6.12.2 §6 — Witness: W-WORKSHOP-1
 */
public class InterimWorkshop {

    /**
     * Recompute half-extents for a variable-length piece.
     *
     * @param product       M_Product (carries width/depth/height in metres)
     * @param forwardAxis   from component_library.db (X, Y, or Z)
     * @param targetLengthM target length in metres (from BOM line qty + UOM)
     * @return [halfW, halfD, halfH] with forward axis replaced, or null if invalid
     */
    public static double[] recompute(MProduct product, String forwardAxis,
                                     double targetLengthM) {
        double w = product.getWidth();
        double d = product.getDepth();
        double h = product.getHeight();

        return switch (forwardAxis) {
            case "X" -> new double[]{ targetLengthM / 2.0, d / 2.0, h / 2.0 };
            case "Y" -> new double[]{ w / 2.0, targetLengthM / 2.0, h / 2.0 };
            case "Z" -> new double[]{ w / 2.0, d / 2.0, targetLengthM / 2.0 };
            default  -> null;
        };
    }

    /**
     * Convert BOM line qty to metres based on c_uom_id.
     */
    public static double qtyToMetres(double qty, String uomId) {
        return switch (uomId) {
            case "MM" -> qty / 1000.0;
            case "M"  -> qty;
            default   -> qty; // EA, KG, M2, M3 — not a length, should not reach here
        };
    }
}
```

### 4. Wire UOM check into PlacementCollectorVisitor.onLeaf()

In `onLeaf()`, BEFORE the half-extent calculation (lines ~330-347),
add UOM dispatch:

```java
// §6.12.2: UOM-driven InterimWorkshop for variable-length pieces
// UOM is the signal — no CUT verb needed (Compiere BOMQty+C_UOM_ID convention)
if (line.isLengthBased()) {
    String fwdAxis = resolveForwardAxis(product);  // from component_library.db cache
    double targetM = InterimWorkshop.qtyToMetres(line.getQty(), line.getUomId());
    double[] trimmed = InterimWorkshop.recompute(product, fwdAxis, targetM);
    if (trimmed != null) {
        halfW = trimmed[0];
        halfD = trimmed[1];
        halfH = trimmed[2];
        BIMLogger.geo("WORKSHOP", "RECOMPUTE {} axis={} target={:.3f}m → halfExtents=({:.4f},{:.4f},{:.4f})",
                productId, fwdAxis, targetM, halfW, halfD, halfH);
    }
}
```

This goes BEFORE expandVerb() — UOM modifies dimensions, verb modifies
positions. They don't overlap. A length-based line always has qty=1
instance count (the length IS the qty).

**Rotation note:** InterimWorkshop recomputes along the **library's**
forward_axis (e.g. Y). If the BOM line has rotation_rule (e.g. 90° to
run along X), the walker applies rotation AFTER recompute. The half-extents
are in local frame; the rotation transforms them to world frame. This is
already how the walker works — no MEP-specific rotation handling needed.

### 5. GEO Forensic Logging

Every InterimWorkshop decision must be traceable via GEO debug log.
The existing GEO TACK channel covers anchor accumulation; add a
WORKSHOP channel for recomputation forensics:

```java
// On entry — proves UOM dispatch fired
BIMLogger.geo("WORKSHOP", "ENTER {} uom={} qty={} qty_type={} fwd_axis={}",
        productId, line.getUomId(), line.getQty(), line.getQtyType(), fwdAxis);

// On recompute — proves dimensions were modified
BIMLogger.geo("WORKSHOP", "RECOMPUTE {} axis={} original=({:.4f},{:.4f},{:.4f}) → target={:.3f}m → half=({:.4f},{:.4f},{:.4f})",
        productId, fwdAxis, product.getWidth()/2, product.getDepth()/2, product.getHeight()/2,
        targetM, halfW, halfD, halfH);

// On guard rejection — proves FIXED piece was NOT modified
BIMLogger.geo("WORKSHOP", "REJECT {} qty_type=FIXED — using library dimensions", productId);

// On tack output — proves outlet position for next sibling verification
double outletAlongFwd = targetM;  // outlet = inlet + length along forward axis
BIMLogger.geo("WORKSHOP", "TACK_IO {} inlet=({:.4f},{:.4f},{:.4f}) outlet_offset={:.4f}m along {}",
        productId, anchor[0], anchor[1], anchor[2], outletAlongFwd, fwdAxis);
```

The TACK_IO line is critical — it lets forensics verify that the next
sibling's dx matches this piece's outlet. If they don't match, there's
a gap or overlap. The GEO log proves chain integrity without runtime
assertions.

For rotation forensics, the existing TACK ROT log already covers:
```
[GEO] TACK ROT 1.5708rad: line=(0.0000,2.3450) → rotated=(2.3450,0.0000)
```
This proves a Y-axis piece was rotated 90° to run along X. Combined
with WORKSHOP RECOMPUTE, the full chain is auditable:
1. WORKSHOP ENTER — UOM dispatch
2. WORKSHOP RECOMPUTE — dimension override
3. WORKSHOP TACK_IO — outlet position
4. TACK ROT — rotation applied
5. TACK LEAF — final placed position

Any session or coder can `grep "WORKSHOP\|TACK" log` and trace every
MEP piece placement decision from UOM to final centroid.
