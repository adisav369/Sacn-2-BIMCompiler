### Defect 1 — FP axis=Z (pendant sprinklers collocated in X/Y)

00g log:


`IfcFireSuppressionTerminal` (sprinkler pendants) hang vertically. Their X/Y

The dominant-axis algorithm picked X or Y (tied, low variance) instead of Z.

**Fix:** Before computing dominant axis by centroid variance, check if the element
ifc_class is `IfcFireSuppressionTerminal`. If yes, force `dominant_axis = Z`

### Defect 2 — Mega-runs (ACMV_L2_RUN_1: 651 pieces in one chain)

00g log:
```
[IFCtoERP] RM_ACMV_L2_RUN_1: 651 pieces, axis=Y, dx=→0→...
```

AABB gap < 50mm produced a single giant chain that spans direction changes
(Y-run segments connected to X-run segments at tee fittings). A real MEP run
is a linear sequence in one dominant direction.

**Fix:** Within each candidate chain (already sorted along dominant axis),
detect direction changes: if two consecutive centroids have a component
*perpendicular* to the dominant axis that is > twice the component *along*
the dominant axis, split the chain at that point. Start a new run.

Formally: for dominant axis A (X, Y, or Z), the other two axes are B and C.
For pair (parent P, child Q):

```
along    = |Q_A − P_A|
perpendicular = sqrt((Q_B − P_B)² + (Q_C − P_C)²)
```

If `perpendicular > 2 * along`, split here — this pair straddles a direction
change (e.g. a tee fitting). The child starts a new run.

The 50mm AABB gap test still applies first (coarse connectivity). The
direction-change test is a second-pass split applied *within* already-connected
chains.
