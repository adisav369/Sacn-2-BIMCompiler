## WHY (three multi-session mysteries, one root — all evidenced, not guessed)
Buildings exist as MULTIPLE unversioned DB copies with silently different contents, and nothing at
load time declares which copy was loaded. Confirmed instances:
1. **Modeller low-LOD fallback (live complaint):** `modeller/Hospital_ARC.db` has 14,641
   `elements_meta` rows and ZERO paired geometry — every `geometry_hash` lookup logs `§BLOB_MISS`,
   only placeholder boxes CAN render. The LOD400 fix (`modeller/real_geometry.js`, `§GEOM-HARDFAIL`,
   see memory `project_modeller_lod400_real_geometry`) is correct code; the DATA a given entry path
   resolves decides the LOD. `*_ARC.db` modeller subsets ≠ `*_extracted.db` fulls.
2. **Stairs flip-flop** (`project_db_snapshot_divergence_landmine`): HHS "0 stairs" published to a
   scoreboard, then flipped to 20 — two copies of the same building disagreed; newer mtime was the
   EMPTIER one.
3. **Hospital trees dead-end** (`prompts/HOSPITAL_TREES_NOT_RENDERING.md`): a session burned its
   window testing against the geometry-less fixture before discovering the pairing gap.

## SPEC
### S0 — Diagnose the live Modeller LOD complaint FIRST (cheapest, answers the user)
Open the Modeller on the building(s) the user sees fall back to low LOD. Read, from the console:
`§GEOM-HARDFAIL` / `§BLOB_MISS` counts + WHICH DB file path was loaded. Record verdict in this file:
- misses > 0 → data plane: that entry path resolves a geometry-less/partial copy. Fix = repair the
  pairing for that path (point it at the full extracted DB, or regenerate the ARC subset WITH its
  `component_geometries`), NOT a rendering change.
- misses = 0 and still boxes → genuine code regression in the real-geometry layer → STOP, record
  findings here, open a separate fix lane (diagnose-in-session, fix-in-other-session).

### S1 — `buildings_manifest.json` (one per app root that serves DBs)
One JSON: building name → { authoritative db path/URL, expected `elements_meta` count, expected
geometry rows (`component_geometries` or paired `_geo.db`/`_library.db`), sha256 (optional first
pass — counts alone already catch every instance above) }. Generated by a small script (node or
python, read-only queries) — NEVER hand-typed numbers. Regenerate on demand; commit the JSON (it is
text, not a DB binary — DB-binary ban unaffected).

### S2 — `§DB_IDENTITY` witness in every loader (Viewer `streaming.js`/`db_resolve.js`, Modeller's
### DB open path)
On every building open, ONE log line:
`§DB_IDENTITY name=<building> path=<resolved db> meta=<n> geo=<n> manifest=<match|MISMATCH|absent>`
- counts come from two cheap COUNT(*) queries at open time;
- MISMATCH → loud `console.warn` + status-bar hint (non-blocking — never brick a load, just make
  the divergence impossible to miss);
- `absent` (building not in manifest) is allowed and logged — additive, zero behavior change.

### S3 — Wire the witness into the standing habit
Any future "building has no X"/"renders wrong" finding MUST quote its `§DB_IDENTITY` line — the
memory rule (`project_db_snapshot_divergence_landmine` "name the exact source file path") becomes
mechanical instead of remembered.

## VERIFICATION (read the log)
- Load 3 known-good buildings (Duplex, BimWhale_Advanced, Hospital full) → `manifest=match`, counts
  equal manifest, zero warns.
- Load the known-bad fixture (`modeller/Hospital_ARC.db`) → `geo=0` + `MISMATCH` warn fires. This
  witness line, had it existed, would have saved two full sessions this month — that is the test
  that names the issue this spec kills.
- Full-stream is NOT needed for any of this (identity reads are COUNT queries at open) — do not
  repeat the 2-minute-streaming-timeout dead end; headless full-streams are only for render checks.
