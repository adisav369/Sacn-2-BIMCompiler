## The math that makes this work

The placement equation (Stage P of the compiler):

    T(e) = T(parent) + R(θ) · Δ(e)

Where:
- T(e) = absolute tack of element e
- T(parent) = absolute tack of parent (room or building)
- R(θ) = rotation matrix (from M_BOM_Line.rotation_rule)
- Δ(e) = (dx, dy, dz) stored in M_BOM_Line

The inverse (what this task implements for ARC elements):

    Δ_new(e) = R(θ)⁻¹ · (T_new(e) − T(parent))

Where T_new(e) comes from the edited DXF position of element e, identified by GUID.

This works for IfcWall / IfcSlab / IfcDoor / IfcWindow (simple placement).
It does NOT apply to MEP (RouteWalker constraint solver) or rule-generated elements.

### Task 2 — DXFSyncVerb.java

New file: `2D_Layout/src/main/java/com/bim/layout/DXFSyncVerb.java`

```java
/**
 * Reads an edited DXF floor plan and computes position deltas per element GUID.
 * Writes deltas back to M_BOM_Line.dx / M_BOM_Line.dy in the intent DB (_BOM.db).
 *
 * ARC elements only: IfcWall, IfcSlab, IfcDoor, IfcWindow.
 * MEP elements are read-only (RouteWalker generates them from rules, not M_BOM_Line offsets).
 *
 * Implements unified_mathematical_formulation.txt §2 Stage P (inverse):
 *   Δ_new = R(θ)⁻¹ · (T_new − T_parent)
 *
 * Witness: W-2D-ARC-ROUNDTRIP
 */
public class DXFSyncVerb {

    /**
     * @param editedDxf   path to the DXF that was edited by the architect
     * @param originalDb  path to the compiled output.db (to read original T(parent) values)
     * @param bomDb       path to the intent DB (_BOM.db) — receives the Δ updates
     * @return SyncResult: count of elements updated, list of GUIDs changed
     */
    public SyncResult sync(Path editedDxf, Path originalDb, Path bomDb) throws Exception;
}
```

Algorithm:
1. Open editedDxf with ezdxf (via ProcessBuilder calling a Python helper — see below)
   OR parse DXF xdata directly in Java using ezdxf-generated JSON intermediate.
2. For each LWPOLYLINE with BIMGUID xdata:
   a. Compute centroid of the polyline: T_new = average of all points
   b. Look up original centroid in output.db elements_rtree: T_old = ((minX+maxX)/2, (minY+maxY)/2)
   c. Delta: dx = T_new.x - T_old.x, dy = T_new.y - T_old.y (in metres)
   d. Skip if |dx| < 0.001 and |dy| < 0.001 (no meaningful change — 1mm threshold)
3. For each changed GUID:
   a. Look up M_BOM_Line row in bomDb WHERE guid = ?
   b. UPDATE M_BOM_Line SET dx = dx + delta_x, dy = dy + delta_y
   c. Log: BIMLogger.info(TAG, "SYNC {} dx={:.3f} dy={:.3f}", guid, delta_x, delta_y)
4. Return SyncResult with change count.

**Python DXF reader helper** (`2D_Layout/python/dxf_read_positions.py`):
Since ezdxf is Python-only, write a thin helper that outputs GUID→centroid as JSON:
```python
import ezdxf, json, sys
doc = ezdxf.readfile(sys.argv[1])
result = {}
for e in doc.modelspace():
    if e.dxftype() == 'LWPOLYLINE':
        xdata = e.get_xdata('BIMGUID')
        if xdata:
            guid = [x.value for x in xdata if x.code == 1000][0]
            pts = list(e.get_points())
            cx = sum(p[0] for p in pts) / len(pts) / 1000  # mm → m
            cy = sum(p[1] for p in pts) / len(pts) / 1000
            result[guid] = [cx, cy]
print(json.dumps(result))
```
DXFSyncVerb calls this via ProcessBuilder, parses the JSON.
