## Background

00p established three gaps:
- **G1:** `_import_joint_piece_types` has no `discipline` column
- **G2:** RM CW/SP unresolvable at element level (IFC2x3 generic classes)
- **G3:** `IFCtoERP.discFromClass()` ignores `elements_meta.discipline`

§6.12.3 resolves G2 via the hybrid pattern architecture:
- Anchors (source/terminal XYZ points) extracted from RM by IFCtoERP → `ad_mep_anchor`
- Patterns (topology step sequences) mined from TE (CW+SP) → `ad_mep_pattern`
- RouteWalker (00r) applies pattern to anchors within ARC envelope → CW/SP BOM lines

This session (00q) covers the three foundation steps: schema, pattern mining, anchor extraction.

### B1. CW pattern — mine from TE

Query the 619 CW IfcPipeSegment elements and 638 CW IfcPipeFitting elements:

```sql
SELECT em.ifc_class, em.element_type, em.discipline, em.storey,
       r.minX, r.maxX, r.minY, r.maxY, r.minZ, r.maxZ,
       (r.maxX+r.minX)/2 as cx, (r.maxY+r.minY)/2 as cy, (r.maxZ+r.minZ)/2 as cz
FROM elements_meta em
JOIN elements_rtree r ON em.id = r.id
WHERE em.discipline = 'CW'
ORDER BY em.storey, cy, cx;
```

## Task C — Anchor Extraction: RM → ad_mep_anchor

### C1. New method: `extractAnchors(Connection erpConn, String buildingType)`

Read from `DAGCompiler/lib/input/HospitalAuckland_extracted.db` (read-only, same pattern as `readMepElements`).

Anchor classification rules (from §6.12.3 §1, applied to element_name keywords):
- `IfcFlowController` → VALVE
- `IfcFlowTerminal` with "toilet"/"wc"/"urinal"/"basin"/"sink"/"shower"/"trap" → FIXTURE
- `IfcFlowTerminal` with "light"/"fixture"/"lamp" → skip (ELEC, not a pipe anchor)
- `IfcFlowSegment` or `IfcFlowFitting` at storey boundary Z (within 200mm of floor/ceiling slab Z) → METER candidate
- All remaining → GENERIC

For each element, emit anchor(s):
- If AABB length (max dim) > 3× min dim (elongated = pipe): emit two anchors at AABB ends
- Otherwise: emit one anchor at AABB centre
