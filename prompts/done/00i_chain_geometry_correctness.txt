## Context — what 00h left broken

00h fixed FP axis and mega-runs. Three structural problems remain:

### Problem 1: Penetration gaps severing continuous runs

Real MEP runs pass through walls and slabs. The pipe stops at one face of the wall
(say minX of wall AABB) and resumes at the other face (maxX). Gap = wall thickness
(150–400mm). Current gap threshold 50mm → new chain. Wrong.

The same happens at floor slabs for vertical risers (plumbing stacks, electrical
conduit, duct shafts). Cross-floor continuity is completely lost.

**Diagnosis from RM:** `system_nodes/system_edges` tables are empty — no IFC
connectivity graph available. Gap classification must use structural geometry.

**Fix:** Before starting a new chain at gap > 50mm, check if the gap interval on
the dominant axis overlaps any structural AABB (IfcWall, IfcSlab, IfcColumn,
IfcBeam) in the extracted DB. If yes → penetration → continue the chain. If no
structural AABB covers the gap → genuine disconnection → new chain.

Load structural AABBs once per building (read-only from `*_extracted.db`) before
the grouping loop. Index them by axis ranges for fast overlap lookup.

Gap override: penetration gaps up to 600mm are valid (thick concrete core walls).
Beyond 600mm with no structural AABB → genuine break regardless.

### Problem 2: Degenerate chains with all-zero offsets

00h result: 1754 of 1802 TE runs have all-zero dx/dy/dz offsets. These are being
written to M_BOM_Line as valid placement data. They are not.

A chain where every consecutive pair has centroid delta < 5mm on all axes means:
- The elements are co-located (fittings stacked on same point), OR
- The chain is on the wrong axis (elements scattered, not linear), OR
- The sort produced a random ordering with no spatial meaning

**Cheating rule:** Do NOT write M_BOM_Line rows for a chain where the sum of all
|dx|+|dy|+|dz| across all pairs is < 10mm. Discard the chain entirely. Log it:

```
[IFCtoERP][GEO] RM_CW_L1_RUN_4: DISCARD degenerate chain — 5 pieces, total offset=0.002m
```

A discarded chain has no M_BOM and no M_BOM_Line. Do not write a shim-only stub.

### Problem 3: Collinearity not verified

Current code sorts elements along dominant axis by centroid, then chains touching
elements. But elements may be touching on the AABB face yet scattered in 3D
(e.g., fittings clustered around a junction point, all within 50mm of each other
but not in a line).

**Fix:** After assembling a candidate chain, compute collinearity R²:
- Take centroid coordinates (cx, cy, cz) of all elements in the chain
- Fit a line through them (least-squares: project all centroids onto the best-fit
  line, compute R² = 1 − SS_res/SS_tot)
- If R² < 0.5 → chain is scattered, not linear → DISCARD with GEO log
- If 0.5 ≤ R² < 0.8 → chain is approximate → write it but log WARN:

```
[IFCtoERP][GEO] RM_ACMV_L2_RUN_17: WARN collinearity R²=0.63 — 12 pieces (approx linear)
[IFCtoERP][GEO] RM_ACMV_L2_RUN_5: DISCARD collinearity R²=0.31 — 8 pieces (scattered)
```

### Problem 4: No rotation captured at direction joints

`M_BOM_Line` has dx/dy/dz but no rotation. At an elbow or tee, the next element
rotates relative to the previous. Without rotation, the walker cannot know which
face of an elbow is the outlet.

**Fix:** Add `rotation_rule` column to M_BOM_Line (REAL, degrees, default 0.0).
For each consecutive pair where the direction changes significantly:

```
rotation_deg = atan2(perpendicular, along) × (180/π)
```

Where `along` and `perpendicular` are as defined in splitByDirectionChange.
Write rotation_deg on the child M_BOM_Line row. Zero for straight segments.

This is a hint, not a precise orientation. It tells the walker "turn approximately
N degrees here." Fine-grained orientation refinement is deferred.

### Problem 5: Coverage topology — no storey, uniform ceiling plane

Buildings with null storey for >80% of MEP (TE, terminals, warehouses) have no
routing topology — MEP is a uniform coverage layer. Chain detection produces
degenerate output (all NULL storey groups, all-zero offsets, wrong axis).

**Fix:** Detect coverage topology before the grouping loop:

```java
long nullStoreyCount = elements.stream()
    .filter(e -> e.storey == null || e.storey.isBlank()).count();
boolean coverageTopology = (nullStoreyCount * 100 / elements.size()) > 80;
```

If `coverageTopology`:
- Skip `detectChains()` entirely
- For each element, compute `dz_standoff = element_cz − ceiling_Z`
  where `ceiling_Z` = max Z of structural AABBs in the building
- Group by `(disc, ifc_class, round(dz_standoff * 20) / 20.0)` — 50mm bands
- Write ONE M_BOM recipe per group: SHIM → ELEMENT at (0, 0, dz_standoff)
- qty on the DISC OrderLine comes from `discipline_counts` (already written by S103)
- Log:

```
[IFCtoERP][GEO] Terminal: COVERAGE TOPOLOGY — 87% null storey
[IFCtoERP] ST: 14 archetypes (FP×3, ACMV×5, CW×4, ELEC×2), ceiling_Z=12.340m
```

This is honest: one archetype per element type at its actual standoff. The
discipline_counts drive qty — not spatial chain count.

### Penetration check (inline in detectChains or wrapper)

```java
private static boolean isPenetrationGap(
        MepPosElement prev, MepPosElement next, char axis,
        List<double[]> structuralAabbs) {
    double gapStart = switch(axis) {
        case 'X' -> prev.maxX; case 'Y' -> prev.maxY; default -> prev.maxZ; };
    double gapEnd   = switch(axis) {
        case 'X' -> next.minX; case 'Y' -> next.minY; default -> next.minZ; };
    double gapSize = gapEnd - gapStart;
    if (gapSize <= 0 || gapSize > 0.6) return false; // 0–600mm only
    int axisIdx = axis == 'X' ? 0 : axis == 'Y' ? 2 : 4;
    for (double[] aabb : structuralAabbs) {
        // structural AABB overlaps the gap interval on dominant axis?
        if (aabb[axisIdx] <= gapEnd && aabb[axisIdx+1] >= gapStart) return true;
    }
    return false;
}
```

Modify `detectChains` signature to accept `List<double[]> structuralAabbs` and
call `isPenetrationGap` when gap > 0.05m.

### Collinearity R² (private static helper)

```java
/** R² of centroid positions projected onto best-fit line. 1.0 = perfect line. */
private static double collinearityR2(List<MepPosElement> chain) {
    // Compute centroid mean, covariance matrix principal direction (or just
    // use the dominant-axis variance as numerator, total variance as denominator
    // for a fast approximation)
    // R² ≈ max(varX,varY,varZ) / (varX+varY+varZ)
    // This is the fraction of total variance explained by one axis — good proxy.
}
```

This approximation is fast and sufficient: R²=1.0 means one axis holds all
variance (perfect line); R²=0.33 means variance is equal on all axes (scattered).
