### 2. Shim matching in walker

New code in CompileStage or RouteStage: when the walker encounters a shim
M_BOM_Line, it matches to an ARC element:

```java
// Shim matching: find ARC host element for this shim
if (product.isShim()) {
    String hostClass = product.getHostIfcClass();  // e.g., "IfcCovering"
    String mount = product.getMount();              // BOTTOM/SIDE/TOP
    // Query ARC c_orderline for matching host in this room/floor
    Point3D hostPos = findHostElement(compileDb, hostClass, roomRef);
    // Shim position = host position + mount offset
    shimPos = applyMountOffset(hostPos, mount, product.getOffsetMm());
}
```

The match is by `ifc_class` + position containment. ARC doesn't know MEP
exists. MEP doesn't reference ARC BOM directly. The shim is the interface.

## CRITICAL GAP — blocks J3 completion

**00c extracted piece types + dimensions but NOT inter-piece tack offsets.**

IFCtoERP currently classifies ifc_class -> piece_type and estimates diameter from
AABB. It does NOT compute the dx/dy/dz between connected pieces (child pos - parent
pos). Without these offsets, the M_BOM_Line has extraction-relative positions (from
VerbFactorizer) but not the piece-to-piece chain offsets that 6.12.2 requires.

The tack offset extraction is J1 proper — the foundation. Must be done in IFCtoERP
while reading *_extracted.db (only moment both pieces' positions are available).
