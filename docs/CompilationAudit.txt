  FINDING F0: C_BPartner / DocSubType Misuse
  ───────────────────────────────────────────
  The pipeline currently reads C_Order.c_bpartner to obtain the building subtype ("SH","DX")
  and passes it as the Java field `cbpartner` through BuildingEntry. This value is then used
  in 4 critical decision points:
    - TemplateStage.shouldSkip():  !"ST".equals(ctx.entry().cbpartner())
    - ProveStage skip:             "ST".equals(ctx.entry().cbpartner())
    - populateCoEmptySpace():      reads c_bpartner FROM c_order to look up M_BOM.doc_sub_type
    - L2 ST-mode guard:            !"ST".equals(ctx.entry().cbpartner())

  Per iDempiere convention, C_BPartner is the customer/vendor — NOT a document classification.
  The correct lookup path is:
    C_Order.C_DocType_ID → JOIN C_DocType → C_DocType.DocSubType
  M_BOM.doc_sub_type was already migrated (M1: c_bpartner→doc_sub_type). C_Order.c_bpartner
  was kept and agreed to be repurposed for real vendor/customer in future.

  The code WORKS (same string values flow through) but violates iDempiere naming.
  Fix: pipeline should derive DocSubType via C_DocType_ID join, not from c_bpartner.
