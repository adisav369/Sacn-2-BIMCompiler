**The GableRoofMesh generator:**

```java
public final class GableRoofMesh implements ParametricMesh {
    @Override
    public MeshResult generate(MeshParameters params) {
        double pitchRad = Math.toRadians(params.getOrThrow("pitch_deg"));
        double spanMm   = params.getOrThrow("span_mm");
        double overhang  = params.getOrThrow("overhang_mm");
        String ridgeAxis = params.getStringOrThrow("ridge_axis");
        
        // Pure arithmetic — vertices from parameters
        double halfSpan  = spanMm / 2.0;
        double ridgeZ    = halfSpan * Math.tan(pitchRad);
        double totalSpan = spanMm + (2 * overhang);
        
        // 6 vertices for gable prism
        List<double[]> vertices = List.of(
            new double[]{-totalSpan/2, 0,      0},       // base SW
            new double[]{ totalSpan/2, 0,      0},       // base SE
            new double[]{ totalSpan/2, depth,  0},       // base NE
            new double[]{-totalSpan/2, depth,  0},       // base NW
            new double[]{0,            0,      ridgeZ},  // ridge S
            new double[]{0,            depth,  ridgeZ}   // ridge N
        );
        
        // 8 faces for gable (2 slopes + 2 gable triangles + 4 soffit)
        List<int[]> faces = computeGableFaces();
        
        // Validate
        BoundingBox bounds = BoundingBox.fromVertices(vertices);
        if (bounds.volume() <= 0) 
            throw new DimensionalContractViolation("Zero-volume gable roof");
        
        return new MeshResult(vertices, faces, bounds, 
            "COMPUTED_FROM_PARAMS:GABLE_ROOF_MY");
    }
}
```

## Where Mesh2Library Fits in the MRP BOM Hierarchy

A fabricated mesh component is a **leaf node** in the GGF → GF → Parent → Child → Leaf
hierarchy described in `docs/TECHNICAL_BUILDING_GUIDE.md §0.1` and `docs/PREFAB_ARCHITECTURE.md`.

```
GGF: UNIT_DUPLEX_STD
  └─ GF: FLOOR_1_STD
       └─ Parent: LIVING_ROOM_STD (room BOM)
            └─ Child: LIVING_SET (furniture BOM)
                 └─ Leaf A: Sofa           ← catalog product (ad_product_dim lookup)
                 └─ Leaf B: GABLE_ROOF_MY  ← FABRICATED (ad_parametric_mesh_param)
```

**Two leaf paths — same three-table authority rule:**

| Leaf type | Shape source | Position source | Dims source |
|-----------|-------------|-----------------|-------------|
| Catalog product | `ad_product_dim` (width/depth/height) | `m_attribute` (dx/dy/dz) | `ad_product_dim` |
| Fabricated mesh | `ad_parametric_mesh_param` (pitch/span/overhang) | `m_attribute` (dx/dy/dz) | `ad_product_dim` (generated bbox) |

The `m_attribute` placement anchor is identical for both. Only the shape source differs.

**Attribute placement metadata for fabricated parts:**
When a fabricated mesh is a BOM child, its placement attributes come from the same
`ad_element_rule` row as any other element:
- `host_type` / `host_ref` — which room or building it attaches to
- `position_rule` — FRACTION, BOUNDARY, or ABSOLUTE (avoid ABSOLUTE)
- `height_mm` / `height_extent_mm` — mounting height + vertical extent
- `orientation` — rotation rule (literal radians or semantic)

For roofs specifically: `ad_roof_preset` (region × building_type → mesh_type) provides
the default selection. DSL `ROOF PRESET` resolves via this table. No hardcoding.
