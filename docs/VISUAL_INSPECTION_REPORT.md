## Finding 1: GOOD — Faithful Federation Extraction

The reference DBs are clean, ad-verbatim extractions of the source IFC files.
- SampleHouse: 55 elements (walls, doors, windows, slabs, roof, furniture, framing)
- Duplex: 1,085 elements (2 merged IFC models — ARC + MEP in single federated DB)

**No spurious elements in reference DBs.** The extraction code (`tools/extract.py`) faithfully
translates IFC geometry to bounding boxes in the spatial DB schema. Class names, discipline
tags, storey assignments, and element dimensions are preserved from source.

## Finding 2: GAP — Compiler Emits Spurious Elements (Engine Inertia)

The output DBs contain **significantly more elements** than reference:

| Stone | Reference | Output | Excess | Ratio |
|-------|-----------|--------|--------|-------|
| SampleHouse | 55 | 141 | **+86** | 2.6x |
| Duplex | 1,085 | 1,840 | **+755** | 1.7x |
| Terminal | 14,080 | 21,401 | **+7,321** | 1.5x |

### What the engine adds that the reference does NOT have:

**IfcSpace (room volumes)** — Engine writes room volumes as spatial elements.
Reference DBs contain zero IfcSpace elements.
- SampleHouse: +3 (living, entrance, bedroom)
- Duplex: +20 (10 per unit)
- Terminal: +37

**MEP elements from compiled pipeline** — The engine's MEP compilation chain (HVAC diffusers,
alarms, sprinklers, lights, outlets, switches, fans, pipes) generates elements independently
of the metadata placement path. These duplicate or exceed reference counts:
- SampleHouse: +48 MEP elements (ref has zero MEP — it's a pure ARC model)
  - 9 IfcPipeSegment, 6 IfcPipeFitting, 6 IfcAirTerminal, 5 IfcOutlet,
    3 IfcSwitchingDevice, 3 IfcLightFixture, 3 IfcFireSuppressionTerminal,
    3 IfcFan, 3 IfcAlarm, 3 IfcCovering
- Duplex: +261 compiled MEP beyond reference counts
  - 32 IfcAirTerminal (ref: 0), 30 IfcOutlet (ref: 0), 22 IfcLightFixture (ref: 0),
    20 IfcFan (ref: 0), 20 IfcCovering (ref: 0), 18 IfcSwitchingDevice (ref: 0),
    16 IfcFireSuppressionTerminal (ref: 0), 6 IfcSanitaryTerminal (ref: 0),
    49 IfcPipeSegment (ref: 0 as separate class), 32 IfcPipeFitting (ref: 0)
- Terminal: similar pattern — compiled MEP overlaps with metadata MEP

**Structural elements from compiled pipeline** — Beams, columns, members generated by
StructuralWriter beyond what reference contains:
- SampleHouse: +9 IfcBeam, +7 IfcColumn (ref: 0 of each)
- Duplex: +47 IfcBeam (ref: 8), +18 IfcColumn (ref: 0), +199 IfcMember (ref: 4)
- Terminal: +625 IfcBeam (ref: 432), +127 IfcColumn (ref: 158), +1727 IfcMember (ref: 442)

**Extra walls/slabs from compiled pipeline** — Wall and slab compilation generates additional
elements beyond metadata placement:
- SampleHouse: +5 IfcPlate (ref: 6 IfcPlate + 5 IfcWall)
- Duplex: +62 IfcPlate (ref: 0), +18 IfcSlab (ref: 21), +28 IfcWindow (ref: 24)
- Terminal: +660 IfcPlate, +716 IfcSlab, +269 IfcWindow, +102 IfcWall, +98 IfcDoor

### Root Cause: Engine Inertia

The compilation pipeline has **two emission paths** that now overlap:

1. **Compiled path** (StoreyCompiler → MEPWriter → StructuralWriter): Generates elements from
   room definitions, BOM recipes, and construction rules. This was the original engine before
   Rosetta. It computes approximate positions from room geometry.

2. **Metadata path** (PlacementAD → emitGlobalPlacementElements): Emits elements at exact
   reference positions from `ad_element_placement`. Added in Phase B2 for positional fidelity.

Both paths run. Both emit elements. The metadata elements land at exact positions (100%
fidelity). The compiled elements land at approximate positions. **The checker matches
reference to nearest output → picks the metadata element (exact) → scores 100%.** The excess
compiled elements are invisible to the checker but visible in the 3D view.

## Finding 3: GAP — Furniture as Bounding Boxes

Compiled furniture elements are bounding boxes, not LOD400 geometry. The reference DBs contain
furniture with extracted mesh geometry (from source IFC). The output DBs contain:
- Metadata-placed furniture: correct position, but bounding-box geometry
- Compiled furniture: approximate position AND bounding-box geometry

The component library has 8,766 LOD400 components, but the furniture placement pipeline
writes bounding boxes from BOM dimensions rather than linking to library mesh geometry.

---

## Finding 4: GAP — X-Ray Scoring Is One-Directional (Optimistic)

The spatial_checker's X-ray and positional scoring measure:
- **Reference → Output**: For each reference element, find the nearest matching output element.

This does NOT measure:
- **Output → Reference**: For each output element, is there a corresponding reference element?

**Consequence:** Excess output elements (the +86/+755/+7,321 surplus) are invisible to the
score. The 100% positional fidelity means "every reference element has a match" — it does NOT
mean "the output is a faithful replica with nothing extra."

A true fidelity score should penalize:
- **Surplus elements** — things the engine adds that the reference doesn't have
- **Wrong-class elements** — IfcSpace where reference has none
- **Duplicate elements** — same position from both compiled and metadata paths

### Proposed Metric: Precision + Recall

| Metric | Definition | Current |
|--------|-----------|---------|
| **Recall** (current score) | ref elements matched in output / total ref elements | 100% |
| **Precision** (not measured) | output elements matched in ref / total output elements | ~38-74% |
| **F1** | harmonic mean of precision and recall | ~55-85% |

Estimated precision by stone:
- SampleHouse: 55 ref / 141 output = ~39% precision (F1 ~56%)
- Duplex: 1,085 ref / 1,840 output = ~59% precision (F1 ~74%)
- Terminal: 14,080 ref / 21,401 output = ~66% precision (F1 ~79%)

## Remediation Plan

### Priority 1: Eliminate Spurious Compiled Elements
The engine should emit ONLY what metadata directs. Elements not in `ad_element_placement`
should not appear in output. This means:
- **Disable compiled MEP** on compiled storeys when metadata covers it
- **Disable compiled structural** when metadata covers it
- **Remove IfcSpace emission** (not in any reference DB)
- **Remove compiled furniture** where metadata furniture exists at same position

The metadata path is the source of truth. The compiled path should only fill gaps where
metadata has no coverage (e.g., SampleHouse has no MEP metadata — should it have MEP at all?).

### Priority 2: LOD400 Furniture Geometry
Link furniture placement to component library mesh geometry instead of writing bounding boxes.
The library has the meshes. The placement has the positions. Wire them together.

### Priority 3: Bidirectional X-Ray Scoring
Add `--precision` flag to spatial_checker that measures output→reference matching.
Report both recall (current) and precision (new). Score should be F1.

### Priority 4: Dedup Metadata vs Compiled
Where both paths emit elements at the same position, keep metadata (exact), remove compiled
(approximate). Or: suppress compiled emission entirely for classes covered by metadata.
