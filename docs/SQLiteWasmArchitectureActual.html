How the Database Works

The big picture — no server, everything lives in the browser tab
1

The browser tab IS the database

There's no server to talk to. When you open a building or the shop, the browser downloads a database file and runs the whole query engine itself, right there in the tab.

↓
2

Two separate filing cabinets

Building files (walls, pipes, floors) and business files (orders, stock, payroll) are kept apart — different files for different jobs, never mixed into one.

↓
3

The whole file loads, every time

Opening a building downloads that building's entire file into memory — not just the part you're looking at. A bigger building means a bigger download and more memory used.

There's a faster "load only what you need" mode designed in, but it isn't switched on yet.

↓
4

Smooth scrolling is a screen trick, not a database trick

Huge buildings still scroll smoothly because we only draw what's on screen — the database itself already holds everything, whether it's visible or not.

↓
5

Search gets a turbo mode

The shop's search box uses a beefed-up version of the engine so typing a name or item finds it instantly, instead of scanning everything line by line.

The one thing to remember

No always-on server. One file per job. The whole thing loads up front, and the screen — not the database — is what stays fast.
