1. WHAT WAS BUILT
===============================================================================

A. PlacementProver.java — Mathematical Placement Validator
   Location: DAGCompiler/src/main/java/com/bim/compiler/validation/PlacementProver.java
   Lines:    ~1,176

   14 proofs organized in 5 tiers of increasing scope:

   TIER 1: Per-Element Arithmetic (every element, no external data needed)
     P01  POSITIVE_EXTENT     Every bbox has dx>0, dy>0, dz>0
     P02  FINITE_COORDS       No NaN, no Inf, coords within [-100, 1000]m
     P03  MIN_DIMENSION       Smallest axis > 1mm (not degenerate sliver)
     P04  STOREY_Z_BAND       Element Z range within expected storey band ± tolerance

   TIER 2: Pairwise Relations (element-vs-element, no external data)
     P05  NO_DUPLICATE_POSITION  No two same-class elements share a centroid (1mm)
     P06  NO_SAME_CLASS_OVERLAP  No same-class elements in same storey overlap

   TIER 3: Host-Element Containment (requires relational metadata from library)
     P07  OPENING_CONTAINED    Every IfcDoor/IfcWindow projects within host wall
     P08  FURNITURE_IN_ROOM    Every furniture centroid lies within host room
     P09  FIXTURE_ON_SURFACE   Every fixture shares face with host wall surface

   TIER 4: Topological Closure (requires wall face + room data)
     P10  PERIMETER_CLOSURE    Exterior walls form a closed polygon (even vertex degree)
     P11  WALL_COVERAGE        Each room face is fully covered by walls
     P12  ROOM_HAS_DOOR        Every habitable room has at least one door

   TIER 5: Conservation Laws (requires grid + slab data)
     P13  PERIMETER_LENGTH     Sum of exterior wall lengths = building grid perimeter ± 10%
     P14  FLOOR_AREA           Sum of room floor areas ≈ total slab area ± 10%

B. Window Transparency Pipeline
   Data flows from the editable data layer through to GLTF export:
     ad_element_placement.material_rgba → PlacementAD.Placement.materialRgba()
     ad_element_rule.material_rgba      → RelationalResolver → PlacementAD
     PlacementAD → MeshBinder.bind() → BoundElement.materialRgba()
     BoundElement → BuildingWriter.writeBoundElement() → elements_meta.material_rgba
     elements_meta → export_to_gltf.py → parse_rgba() → alphaMode="BLEND"

   Data layer values for IfcWindow:
     - 0.700,0.850,0.950,0.300  (alpha=0.3, light blue glass — float format)
     - 180,220,255,160           (alpha≈0.63, blue glass — int-255 format)
     - 0.000,0.502,0.753,0.100  (alpha=0.1, deep blue glass — float format)

   GLTF exporter auto-detects format (float vs int-255) and applies:
     - alpha < 1.0 from data layer → respected as-is (authoritative)
     - alpha = 1.0 → class-based fallback (IfcWindow=0.3, IfcCurtainWall=0.2)
     - alpha = 0.0 → treated as error, forced to 1.0

C. E2E Integration
   - Pre-write:  BuildingWriter.write() runs PlacementProver.prove() before emission
                  (diagnostic — violations reported but don't block emission)
   - Post-write: All 4 E2E tests run PlacementProver.proveFromDB() after DB write
   - Non-blocking: violations are warnings, not failures. Score remains arbiter.


===============================================================================
2. WHY THIS IS CORRECT
===============================================================================

A. Proofs are Pure Functions
   Every proof is: (PlacementData) → ProofResult
   No side effects. No database writes. No global state mutation.
   Input is a snapshot of placement coordinates + metadata.
   Output is an enum: PROVEN | VIOLATED | SKIPPED.

B. Tiered Degradation
   Tier 1-2 proofs run on raw coordinates (always available).
   Tier 3-5 proofs require relational metadata; if unavailable, they return
   SKIPPED (not VIOLATED). This means:
     - Terminal (no relational data yet) skips T3-T5 gracefully
     - New buildings without ad_room_boundary don't fail false-positive

C. No Hardcoding Introduced
   - Coordinate range [-100, 1000]: parametric constant, not building-specific
   - Storey Z bands: derived from storey name pattern matching, not fixed heights
   - Wall/room geometry: loaded from ad_wall_face + ad_room_boundary (data layer)
   - Element rules: loaded from ad_element_rule (data layer)
   - Building perimeter: computed from ad_building_grid (data layer)
   All thresholds use BIMConstants (PLANE_TOLERANCE=50mm, ASSEMBLY_TOLERANCE=10mm)
   or well-documented local constants with clear physical meaning.

D. Score Not Affected
   The prover is non-blocking: it reports violations but does NOT:
     - Prevent emission of elements
     - Modify placement coordinates
     - Change the output DB in any way
   Score remains 100% for SH, DX. Terminal remains ~100%. TB-LKTN remains 58.

E. Window Transparency: Data Layer is Authoritative
   Alpha values live in the same ad_* tables as all other element properties.
   The compiler passes them through without modification.
   The GLTF exporter respects data-layer alpha as Priority 1.
   No hardcoded alpha values for specific buildings or elements.

6. ARCHITECTURE DECISION: NON-BLOCKING PROOF
===============================================================================

The prover was deliberately designed as non-blocking (report, don't throw).

Rationale:
  1. Score is the arbiter. If the score is 100%, a P06 overlap violation is noise
     from bbox approximation, not a real placement error.
  2. Violations are improvement signals, not blockers. They tell the developer
     "this element MIGHT be wrong" without preventing compilation.
  3. Critical vs non-critical: P01-P04, P07 are marked critical (isCritical()).
     The pre-write block in BuildingWriter logs a warning if critical proofs fail.

ARCHITECTURAL BOUNDARY (per watchdog review):
  - BoundElement constructor = THE GATE. It enforces mesh-fits-bbox at construction
    time. If the contract fails, the element degrades to parametric.
  - PlacementProver = THE AUDIT. It reports spatial/topological anomalies after the
    fact. It must NEVER gate emission — that's BoundElement's job.
  - If a proof belongs in the gate, it should move into BoundElement's constructor
    invariant, NOT into the prover's critical path.
  - Terminal prover GATED behind relational data check (ad_room_boundary) to prevent
    58K noise violations from eroding signal quality.

This matches the Rosetta Stone philosophy: measure convergence, don't enforce
arbitrary gates that would block progress.
